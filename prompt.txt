What demonstrably works today (verified by `make check`, exit 0, and by CI on
Python 3.10, 3.11, 3.12 and 3.13):

  - traceshield.Sanitizer sanitizes attribute values: strings, JSON-encoded
    documents, mappings and sequences. Structure survives; only sensitive leaves
    change. A Finding is emitted per redaction, carrying rule, category,
    severity, confidence, action, attribute key, JSON path, detector and a salted
    digest — and no field that can hold the value itself.
  - Detection combines four deterministic signals: a 19-rule pattern pack,
    checksum verifiers (Luhn, IBAN mod-97, Verhoeff, JWT header), charset-aware
    entropy scoring that excludes UUIDs, timestamps, filesystem paths, URLs and
    dotted names, and key-name escalation.
  - Actions: mask, partial, hash, drop. Fail-closed on budget breach, detector
    failure and unexpected internal error. Output is idempotent and deterministic.
  - Gate: ruff format and lint, mypy --strict, 267 tests, 99.64% coverage against
    a 90% floor, bandit, pip-audit, sdist and wheel build. CI runs the same on
    Python 3.10 through 3.13, with actions pinned by commit SHA.
  - tests/test_readme.py executes the README quickstart and compares it against
    the documented output, and tests/test_handoff.py keeps this file and the
    tracker in step, so neither the docs nor this handoff can drift silently.

Known gaps — do not describe any of these as working:

  - No OpenTelemetry integration and no CLI. The engine is not wired to anything.
  - Policy loading from an external document does not exist. Only Policy.default()
    and Policy.build(). It arrives with the CLI task, which needs it.
  - Non-string leaves are not scanned, so an identifier stored as a JSON number is
    missed. Replacing it would change the node's type.
  - Base64 blob parts are dropped rather than scanned.
  - Entropy scoring skips paths, URLs and dotted names, so an unnamed base64
    secret containing several slashes can be missed unless a named rule or its

  - No latency measurement exists anywhere. Do not put a number in the README,

YOUR TASK: TS-005 — OpenTelemetry SanitizingSpanExporter
--------------------------------------------------------------------------------

Full detail, including all ten acceptance criteria, is in docs/Tracker.md under
TS-005. Read it there; this is only the orientation.

Outcome: a user adds one line to their OpenTelemetry setup and every exported
span is sanitized before it leaves the process.

    provider.add_span_processor(
        BatchSpanProcessor(SanitizingSpanExporter(OTLPSpanExporter(), sanitizer=sanitizer))
    )

The binding constraint, settled in ADR 0003: ReadableSpan is immutable at
SpanProcessor.on_end, so redaction cannot happen in a span processor. Wrap the
exporter. Read ADR 0003 before writing code.

The two criteria most likely to be got wrong:

  - Span identity must be byte-equal through sanitization: trace ID, span ID,
    parent, name, kind, start and end time, status, links, resource attributes
    and instrumentation scope. Only attribute values may change. Test it.
  - export() must never raise or report failure because of sanitization, but a
    failing delegate exporter is the caller's failure and must be reported
    faithfully. The two cases must be distinguishable.

OpenTelemetry is an optional extra. `import traceshield` must keep working with
opentelemetry-sdk absent.
